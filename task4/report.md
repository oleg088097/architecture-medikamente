# Оценка узких мест при миграции


## Инфраструктура

AI аналитика может потребовать графических ускорителей
- На этапе планирования провести оценку требований планируемых к использованию алгоритмов и моделей

Аналитика потребует дополнительных хранилищ кроме основных для хранения datalake и обработанных данных
Построение аналитики потребует вычислительных мощностей
- Использовать облако (только) для обезличенных аналитических данных после Anonymization Service; ПДн и мед. данные — только on-prem.
- Иначе требуется заранее рассчитать ожидаемые объёмы данных и требуемые мощности и подготовить сервер 
- Использовать холодное хранилище для долгосрочного хранения аналтических данных 

В данный момент система состоит из 1 физического сервера. Для хранения резервных копий потребуется ещё один, а для повышения доступности системы - больше. Использование облака может быть невозможно ввиду регуляторных ограничений.
- Хранить резервные копии  на файловом сервере без больших вычислительных возможностей или на внешней системе хранения данных (NAS)
- Если есть возможность использовать облако с соблюдением регуляторных ограничений, то вынести в него часть сервисов для гибридного формата
- Для повышения уровня доступности разместить больше физических серверов

## Программное обеспечение

Центральной частью системы становится МИС, который является сторонней разработкой и от него зависит производительность системы
- Приобрести МИС с возможностью расширения командой или с контрактом доработки продавца
- Использовать МИС с возможностями горизонтального масштабирования

Системы 1С ограничены в поддерживаемых интеграциях
- На этапе планирования проработать ожидаемые интеграции 1С и уточнить их возможность или найти альтернативу

## Интеграция

Разделение монолита увеличивает количество сетевых взаимодействий между частями системы и необходима пропускная способность сети
- Использовать асинхронное взаимодействие при возможности
- Планировать и минимизировать потоки данных
- Выполнять batch-операции в нерабочие часы

Лаборатории имеют фиксированный API, который может быть неудобен для нового стека
- На этапе планирования собрать API лабораторий и запланировать anti-corruption layer

## Персонал

IT-отдел из 3 специалистов маленький. Бизнес-аналитик не разработчик.
- Расширить состав команды для планируемой миграции 
- Вынести разработку менее критичных частей инфраструктуры в аутсорс. Только для некритичных компонентов без доступа к ПДн/мед. данным, с NDA и аудитом.

Отсутствие команды тестирования
- Нанять команду тестирования
- Писать автоматические тесты в момент разработки 

## Процессы

Большое количество шифрования данных требует ресурсов
- Планировать и минимизировать потоки данных
- Использовать аппаратное ускорение криптографии
- Хранить анонимизированные данных в тех случаях, когда не требуется наличие ПДн 

Сбор логов для анализа также требует пропускной способности и дополнительных вычислительных мощностей
- Вынести эту функциональность на отдельную машину или в облако
- Ограничить список сервисов для анализа только критичными (Gateway, MIS, IAM)

ABAC правила требуют настройки и времени для вычисления
- Кэшировать результатов вычисления правил
- Использовать ABAC только там, где необходимо, а в более простых случаях использовать RBAC

Миграция данных из Excel
- Провести оценку целостности данных заранее
- Определить процедуры коррекции/очистки данных

## Приоритет
До MVP:
- Провести найм персонала (разработка, QA)
- Установить второй сервера
- Оценить объем данных
- Создать anti-corruption layer для лаборатории
- Определить процедуры коррекции/очистки данных
- Выбор МИС по требованиям расширения/масштабирования

До Масштабирования:
- Перевести операции на асинхронное/batch-выполнение
- Кэшировать ABAC
- Вынести сбор и анализ логов на отдельный сервер
- Использовать аппаратное ускорение криптографии

После стабилизации:
- Установка GPU
- Гибрид с облаком
- Аутсорс некритичных частей
